# HANDOFF — скидки-мехта-эврика: мониторинг скидок mechta.kz и evrika.com по всем товарам

Документ для модели AI или разработчика, которая создаст отдельный бот
мониторинга скидок в магазинах mechta.kz и evrika.com по всем товарным
категориям. Проект Новый — переиспользует инфраструктуру существующего
GPU-бота, но имеет собственную модель данных и логику.

Дата: 2026-09-12. Статус: проект не начат, есть разведка и результаты аудита
родительского проекта.

Репозиторий родительского проекта: `https://github.com/john88cool-coder/gpu-deals`
(смотрите HANDOFF.md там для справки по инфраструктуре и стилю).

---

## 1. Что это и зачем

Владелец заметил, что mechta.kz и evrika.com периодически дают хорошие скидки
на всю линейку продукции — от смарт-часов до холодильников. Текущий GPU-бот
(gpu-deals) заточен под видеокарты и не может мониторить другие товары.

**Цель**: отдельный бот, который мониторит скидки в mechta.kz и evrika.com
по всем товарным категориям и присылает уведомления в Telegram, когда цена
на интересующий товар падает ниже порога.

**Ключевое отличие от GPU-бота**: нет PassMark-рейтинга, нет VRAM-фильтра,
нет чипов. Вместо этого — товарные категории и общая логика «цена упала
ниже медианы за 14 дней» или «цена упала на N% от исторического максимума».

## 2. Контекст владельца

- Telegram-бот: тот же `@VideoCardPlease_bot`, chat_id `366256716`
  (переиспользуется; при желании можно создать отдельного бота для скидок).
- Владелец хочет мониторить **все категории**, но не сразу всё —
  начать с 2-3 категорий (например, смарт-часы, наушники, телевизоры)
  и расширять по мере надобности.
- Пороги: для каждой категории владелец задаёт максимальную цену
  (или процент от медианы за 14 дней), при котором приходит уведомление.
- Стиль: агрессивный режим (лучше лишнее, чем пропущенное).

## 3. Разведка магазинов (главная ценность — не потерять)

### mechta.kz

- **SPA** (Nuxt-приложение на diginetica search engine): обычный curl получает
  18 КБ пустой оболочки без единого товара. Даже Playwright после ожидания
  и прокрутки — 67 КБ без названий и цен.
- **Товары подгружаются через внутренний API**, который нужно
  реверс-инжинирить: открыть DevTools → Network → XHR при скролле каталога
  и найти endpoint, отдающий JSON с товарами.
- **Возможный путь**: API diginetica (`cdn.diginetica.net` в preconnect) —
  это поисковый движок, у которого есть документированный API для
  e-commerce. Возможно, mechta.kz использует его для каталога.
- robots.txt: `Disallow: *sort=*`, `Disallow: *?q=*` — чистая категория
  `/section/smart-chasy/` разрешена.
- Присланный владельцем URL: `https://www.mechta.kz/section/smart-chasy/`
  — работает в браузере, SPA рендерит 99 товаров с ценами и скидками.
- Скидки видны как зачёркнутая старая цена + бейдж «-71%», «-73%» и т.д.
- Наличие: метки «На витрине», «Осталось мало», «Под заказ».

### evrika.com

- **Категория `/category/videokarti` возвращает HTTP 404** через curl И через
  Playwright — хотя именно этот URL прислал владелец. 404-страница содержит
  415 КБ рекомендаций (принтеры, холодильники) — товары отдаются, но
  категория не находится.
- **robots.txt запрещает `?sort=` и `?f=`** — а URL владельца использует оба
  параметра. Значит, отслеживать категорию с фильтрами нельзя без нарушения
  robots. Чистая категория `/category/<slug>` разрешена.
- **Слаги категорий не угадываются**: `/category/umnye-chasy/`,
  `/category/noutbuki/`, `/category/televidenie/` — все 404. Правильные слаги
  нужно найти на сайте (навигация или sitemap).
- Продукты живут на `/catalog/<slug>/p<id>` — это видно из 404-страницы.
- **Возможный путь**: sitemap.xml на evrika.com не проверен — проверить его
  для списка категорий.

### Что ещё нужно выяснить (сделать ДО написания парсеров)

1. mechta.kz: найти API endpoint для каталога (DevTools → Network → XHR)
2. evrika.com: найти правильные слаги категорий (через sitemap или навигацию)
3. Проверить, отдают ли оба сайта JSON с ценами (многие SPA имеют
   внутренний API, который проще использовать, чем рендерить браузером)
4. Проверить частоту обновления цен (если цены меняются раз в день —
   обход каждые 2 часа избыточен)

## 4. Архитектура

### Переиспользуется из gpu-deals

- `notify.py` — Telegram-доставка (без изменений)
- Структура workflow (Actions, cron, concurrency, ретраи)
- Паттерн хранения (SQLite, retention, VACUUM)
- Паттерн парсеров (SHOP / parse / fetch, paging, dedup)
- Паттерн actions (триггеры, если: always, одиночный writer)

### Новое в этом проекте

- `categories.py` — словарь категорий для мониторинга:
  `{slug, название, порог_цены или порог_%}`
- `evaluate.py` — сигналы: цена упала ниже медианы за 14 дней (универсально),
  цена упала на N% от исторического максимума, цена ≤ целевой
- `parsers/mechta.py`, `parsers/evrika.py` — по результатам разведки API
- `report.py` — свой формат уведомлений (без PassMark, с категорией и брендом)

### Структура проекта

```
skidki-mechta-evrika/
  src/skidki/
    config.py        категории, пороги, Telegram
    models.py        Product (название, категория, бренд, цена, URL, наличие)
    storage.py       SQLite: observations, alerts, categories
    evaluate.py      сигналы: цена упала ниже медианы, цель, исторический min
    notify.py        Telegram (копия из gpu-deals)
    crawler.py       цикл обхода + свод + watchdog
    report.py        форматирование
    parsers/
      mechta.py
      evrika.py
  tests/
  .github/workflows/
    crawl.yml        обход каждые 2 часа
    watchdog.yml     дважды в сутки — тревога при простое
    tests.yml        pytest на push
  deploy/
    install.sh       скрипт установки на VPS
```

## 5. Сигналы и пороги

| Сигнал | Условие | Комментарий |
|---|---|---|
| «цена упала» | ниже медианы за 14 дней на ≥N% | N задаётся владельцем (3-10%) |
| «исторический минимум» | ниже минимума за 30 дней | осторожно: рынок может упасть навсегда |
| «цель» | цена ≤ target_price из конфига | как в gpu-deals |
| «появился в наличии» | был отсутствующим, стал доступным | для позиций с историей |

Магазинная «скидка» (-71%, -73% на скриншоте mechta) НЕ является сигналом —
это та же проблема, что у Technodom с видеокартами: магазин рисует скидку
от завышенной цены. Основание — только собственная история цен.

## 6. Инфраструктура

**GitHub Actions, public репозиторий** (отдельный от gpu-deals).

| Workflow | Расписание | Что делает |
|---|---|---|
| crawl | каждые 2 часа | обход mechta + evrika, оценка, Telegram, коммит базы |
| watchdog | дважды в сутки | тревога, если обходы перестали приходить |
| tests | push | pytest |

**Уроки из gpu-deals (обязательно учесть)**:

- Единый writer: все job, пишущие в базу, — одна concurrency-группа.
- Сохранение базы: `if: always()` на шаге коммита — наблюдения переживают
  отказ Telegram.
- Ретрай установки Playwright (если нужен браузер): apt-источник
  dl.google.com периодически отдаёт hash mismatch.
- Дедупликация: одна позиция — одно наблюдение за обход (paging.py).
- Алерты: record_alert с delivered_at=NULL, подтверждение после успешной
  отправки, дедупликация только по доставленным.
- Экранирование HTML: все названия и ссылки через html.escape.
- Retention: 30 дней + VACUUM после удаления.

## 7. Уроки из разведки mechta/evrika (2026-09-12)

- **mechta.kz** — SPA на diginetica: curl получает пустую оболочку,
  товары рендерятся на клиенте. Нужен либо Playwright, либо реверс API.
  При использовании API — НЕ нужен браузер, что сильно упрощает CI.
- **evrika.com** — серверный рендеринг, но слаги категорий не угадываются.
  robots.txt запрещает `?sort=` и `?f=` — отслеживать категорию с фильтрами
  нельзя. Продукты на `/catalog/<slug>/p<id>`.
- **Не добавляйте витрины без живой разведки** — урок из gpu-deals:
  alser.kz и mechta.kz были предложены владельцу, не проверив, что в них
  вообще продаются видеокарты (в alser и mechta — не продаются).

## 8. Чего НЕ делать

- Не переиспользовать GPU-специфичную логику (INTERESTED_CHIPS,
  PassMark, VRAM) — это другой домен.
- Не добавлять магазины без живой разведки конкретных URL.
- Не отправлять алерт на магазинную «скидку» без проверки собственной
  историей цен — та же ловушка, что и с видеокартами.
- Не делать уведомления длиннее 10 строк — владелец читает с телефона.
- Не хранить пароли и токены в коде — только в .env и Secrets.

## 9. Порядок работы

1. Разведка mechta.kz API (DevTools → Network → XHR на каталоге)
2. Разведка evrika.com API или серверной разметки
3. Написать парсеры (по одному на магазин)
4. Схема БД + сигналы (универсальные, без GPU-специфики)
5. Telegram-уведомления (скопировать из gpu-deals, адаптировать текст)
6. Workflow + CI
7. Смок на живых магазинах, коммит, push
