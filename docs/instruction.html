Раздел 1

Что такое skidki

Это ИС из трёх контуров: обходчик собирает цены магазинов каждые 2 часа → аналитика считает сигналы и честную скидку по истории → панель и Telegram показывают результаты. История хранится отрезками «цена держалась с … по …», что даёт взвешенную медиану вместо шумных снимков.

🛰 Сбор

Парсеры 6 активных + 5 резервных магазинов (Kaspi, WB, Ozon…). Playwright обходит Cloudflare, API-магазины берутся напрямую.

🧠 Аналитика

5 сигналов: скидка, падение к медиане, минимум 30 дней, цель, ресток. Скоринг «лучшего товара» поверх сигналов.

📊 Выдача

Статическая панель на GitHub Pages: топ-выборы, каталог, сравнение, избранное, палитра команд. Плюс Telegram-сводки.

Ключевая идея: зачёркнутая цена магазина — не доказательство скидки. Доказательство — собственная история наблюдений ИС. Всё остальное строится на этом принципе.

Раздел 2

Быстрый старт

1
Откройте панель — главная показывает hero со статистикой, динамику лидера и топ-8 предложений дня.
2
Изучите «Топ» — раздел с готовыми выборами: «Выбор ИС», «Честная скидка», лучшие по value и по группам.
3
Фильтруйте каталог — магазин, группа, бренд, цена, глубина скидки, наличие, избранное и бейджи. Все параметры сохраняются в URL — ссылкой можно поделиться.
4
Жмите ⌘K (или /) — мгновенный поиск по всем товарам и переход между разделами, не отрывая рук от клавиатуры.
5
Сравнивайте и сохраняйте — кнопка «⚖» на карточке добавляет товар в сравнение (до 4), «♥» — в избранное. Оба хранятся в браузере.
Данные обновляются каждые 2 часа автоматически; панель сама подтягивает свежий срез каждые 30 секунд — перезагрузка не нужна.

Раздел 4

Бейджи и метрики

Скоринг считается при каждом экспорте данных и не хранится в базе — значения всегда соответствуют свежей истории.

Выбор ИС

Честная скидка ≥18%, value ≥78, цена ≥20 000 ₸, в наличии. Высшая рекомендация системы.

Честная скидка

Падение к взвешенной медиане за 14 дней подтверждено историей не короче 3 дней.

Топ-Бренд

Бренд из топ-списка рынка KZ (Samsung, Apple, Xiaomi, LG, Sony, Bosch, Dyson…).

Рисованная?

Магазинная скидка превышает честную на 15+ п.п. — зачёркнутая цена завышена. Не приговор, а повод смотреть историю.

value N

Итоговый балл 0–100 из компонентов следующего раздела.

Раздел 5

Как считается value score

0.550.200.150.10
55% — честная скидка
нормирована 0→45% с плавной кривой 20% — доверие к бренду
топ 1.0 · известный 0.8 · noname 0.3 15% — доступность
в наличии 1.0 · витрина/мало 0.6 10% — свежесть
≤6 ч 1.0 · ≤24 ч 0.55 · старше 0.2

Плюс мягкий бонус +5 за внешние оценки (рейтинг ≥4.5 и ≥50 отзывов), если магазин их отдаёт. Итог масштабируется в 0–100. Честная скидка дополнительно режется, если зачёркнутая цена выше медианы рынка на 12%+ — защита от инфляции «было 999 990».

Пример: товар со скидкой −50% на витрине, но история ровная → честная ≈ 0%, бейдж «Рисованная?», value низкий. Тот же товар с реальным падением к медиане → «Честная скидка» и высокий value. Система различает эти случаи.

Архитектура системы

🌐 Playwrightобход Cloudflare, общий контекст браузера

🧠 evaluate.py5 сигналов: deal · drop · low · target · restock
💬 Telegramсводка по группам, кнопки /groups · /status
📈 scoring.pyfair discount → value score → бейджи
📤 export.pylatest.json + history.json → gh-pages
📊 Панель (SvelteKit)7 маршрутов · ⌘K · избранное · сравнение · топы · тёмная тема · PWA

История цен хранится отрезками: «цена P держалась с T1 по T2». Обход с той же ценой продлевает отрезок, а не пишет новую строку — 16k позиций × 12 обходов/сутки не раздувают базу. Медиана считается взвешенно по времени: цена, державшаяся неделю, весит больше двухчасовой распродажи.

Раздел 9

Установка и эксплуатация

Домашний ПК (Windows)

  1. .env.example → .env, вписать TELEGRAM_BOT_TOKEN
  2. pip install -e ".[dev]" и python -m playwright install chromium
  3. powershell -ExecutionPolicy Bypass -File deploy\install_task.ps1 — обход каждые 2 ч
  4. powershell -ExecutionPolicy Bypass -File deploy\install_bot_task.ps1 — слушатель кнопок Telegram
  5. Готово: логи logs\crawl-ДАТА.log, база data\skidki.sqlite3

GitHub Actions

  • crawl — каждые 2 ч: 5 магазинов (кроме mechta), база в кэше Actions, экспорт → gh-pages
  • dashboard — сборка панели при пуше в web/**
  • watchdog — 06:00/18:00 UTC: тревога, если обходов нет >6 ч
  • tests — pytest на фикстурах при пуше в main

Настройка без кода

Пороги и цели — в rules.toml: глубина скидки, минимальная цена, цели по товарам (watch) и категориям (category). Изменения подхватываются следующим обходом.

mechta блокирует IP дата-центров GitHub — этот магазин обходит домашний ПК, остальные пять — Actions. Это гибридная схема, зашитая в расписания.

Раздел 10

Частые вопросы

Почему у товара нет бейджа «Честная скидка»?

История короче 3 дней или падение к медиане меньше порога (7% и 2 000 ₸). Система честно молчит, пока данных мало.

Что значит «Рисованная?»

Магазинная скидка опережает подтверждённую историей на 15+ п.п. Типичный случай — завышенное «было». Смотрите график на карточке товара: ровная история при «−50%» говорит сама за себя.

Где хранятся избранное и сравнение?

В localStorage вашего браузера. Без аккаунта, без сервера, никуда не отправляются.

Как поделиться подборкой фильтров?

Просто скопируйте URL каталога — все фильтры в нём. На главной есть кнопка «Копировать топ-8» — список с ценами и ссылками в буфер.

Данные устарели?

Шапка показывает «обновлено N мин назад». Кнопка ↻ обновляет срез мгновенно; автообновление — каждые 30 секунд. Статус каждого магазина — на странице «Магазины».

Как добавить магазин?

Каркас парсера: модуль с SHOP и async fetch(context, config), регистрация в parsers/__init__.py, метка в export.py. Каркасы Kaspi/WB/Ozon/Satu/DNS уже готовы — останется включить и проверить разметку.
